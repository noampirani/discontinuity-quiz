# משחק אי־רציפות עם חדר כיתתי ו־Leaderboard

משחק בעברית עם 9 גרפים ושאלות אמריקאיות על **אי־רציפות סליקה, קפיצה ועיקרית**. יש שלושה מצבים: חדר כיתתי חי, משחק אישי ומצב הקרנה ללא חיבור.

**גרסת החדר הכיתתי עובדת בין טלפונים ומחשבים דרך Firebase Realtime Database.** המתרגל פותח חדר עם קוד בן 6 תווים; הסטודנטים מזינים כינוי, עונים על אותה שאלה בו־זמנית ורואים טבלת מובילים לאחר חשיפת התשובה. המתרגל רואה כמה הצביעו ואת התפלגות ההצבעות. יש שעון 30 שניות אופציונלי, והחדר נשמר גם אם הדף נטען מחדש באותו דפדפן.

> שימו לב: אי אפשר להפעיל חדר משותף באמצעות GitHub Pages לבדו. נדרש **חיבור חד־פעמי לפרויקט Firebase חינמי משלכם**. בלי חיבור Firebase, המצב האישי ומצב ההקרנה עדיין פועלים. אין צורך ב־Codex, ב־Node.js או בשרת שתתחזקו.

## הגדרה חד־פעמית (בערך 10–20 דקות)

### 1. יצירת פרויקט Firebase

1. היכנסו ל־<https://console.firebase.google.com/> וצרו פרויקט חדש (`Create a project`). אפשר להשתמש בתוכנית **Spark (ללא חיוב)**.
2. בתוך הפרויקט, בחרו **Project Overview → Add app → Web** (האייקון `</>`). רשמו אפליקציית Web וקבלו את אובייקט `firebaseConfig` שמופיע במסך. אין צורך להפעיל Firebase Hosting.
3. בתפריט השמאלי פתחו **Build → Authentication → Get started → Sign-in method**, ובחרו **Anonymous → Enable → Save**. כך סטודנטים יכולים להיכנס בכינוי בלבד, בלי הרשמה.
4. בתפריט השמאלי פתחו **Build → Realtime Database → Create Database**. בחרו אזור גיאוגרפי, התחילו במצב נעול (**locked mode**) והשלימו את יצירת המסד. **לא** להשתמש ב־Cloud Firestore — אלה שני מוצרים שונים.

### 2. חיבור הקבצים לפרויקט

1. פתחו את הקובץ `firebase-config.js` בעורך טקסט והחליפו את חמשת הערכים המתחילים ב־`PASTE_` בערכים של Firebase מתוך **Project settings → Your apps → SDK setup and configuration → Config**.
2. ודאו שהאובייקט כולל גם `databaseURL`. אם הוא לא מוצג ב־SDK config, מצאו אותו ב־**Realtime Database → Data** בראש המסך; כתובתו נראית בדרך כלל כמו `https://PROJECT-default-rtdb.REGION.firebasedatabase.app`. **להעתיק את הכתובת המדויקת** (אין לנחש את האזור).
3. ב־Firebase פתחו **Realtime Database → Rules**. העתיקו **את כל התוכן** של `database.rules.json` אל עורך הכללים ולחצו **Publish**. הקובץ ב־GitHub אינו מעדכן את כללי Firebase אוטומטית.
4. ודאו שהדומיין שממנו תפעילו את המשחק מורשה לשימוש ב־Firebase Authentication, אם Firebase מציג שגיאת `unauthorized-domain` (**Authentication → Settings → Authorized domains**).

**חשוב:** לא להשתמש בכללים פתוחים כמו `".read": true, ".write": true`. הכללים המצורפים אוכפים שמתרגל בלבד ינהל את המשחק, ושכל משתתף ישלח תשובה אחת בלבד לכל שאלה. אין לשים בפרויקט מפתחות שרת (service account או private keys); `firebaseConfig` הוא נתון מזהה של אפליקציית Web ואינו מפתח סודי, ולכן ההגנה היא בכללי המסד.

### 3. העלאה ל־GitHub Pages

1. היכנסו ל־<https://github.com> וצרו מאגר חדש מסוג **Public** בשם `discontinuity-quiz`.
2. בתוך המאגר בחרו **Add file → Upload files**, והעלו את הקבצים לתיקייה הראשית שלו: `index.html`, `live.js`, `firebase-config.js`, `README.md`, `database.rules.json` (וגם `.nojekyll` אם רוצים). לחצו **Commit changes**.
3. בחרו **Settings → Pages → Build and deployment → Deploy from a branch**, אחר כך **main** והתיקייה **/(root)**, ואז **Save**.
4. כשתופיע האפשרות **Visit site**, הכתובת תהיה בפורמט `https://USERNAME.github.io/discontinuity-quiz/`.

אם כבר היה לכם מאגר עם הגרסה הישנה, העלו את קובצי הגרסה החדשה *לאותו מאגר* ואשרו את החלפת `index.html` ואת הוספת הקבצים.

## איך משחקים בפועל?

**במחשב המתרגל:** פותחים את האתר → `משחק כיתתי חי + דירוג` → משאירים או מכבים את שעון 30 השניות → `יצירת חדר חדש`. מקרינים את קוד החדר ומעתיקים את קישור ההזמנה. ברגע שהסטודנטים הצטרפו, לוחצים `התחל משחק`. רואים כמה אנשים ענו ואת ההתפלגות לפי סוג אי־הרציפות. לוחצים `חשוף תשובה וניקוד`; דירוג המשתתפים מופיע ומעודכן אצל כולם. עוברים לשאלה הבאה בלחיצה. אחרי 9 שאלות מופיע הדירוג הסופי. בסוף אפשר ללחוץ `סגור ומחק את החדר` כדי למחוק את הכינויים והתשובות.

**בטלפונים של הסטודנטים:** נכנסים לקישור ההזמנה (הקוד כבר מוזן אוטומטית) → בוחרים כינוי → `הצטרפות למשחק` → ממתינים לשאלה ועונים על ידי לחיצה. ניתן לענות **פעם אחת בלבד לכל שאלה**. אחרי שהמתרגל חושף את התשובה מופיעים הסבר, ניקוד אישי וה־Leaderboard. אפשר גם לפתוח את דף הבית ולהזין קוד ידנית.

**בדיקה לפני השיעור:** פתחו חדר במחשב, וסרקו את קישור ההזמנה בטלפון. לחלופין פתחו את הקישור בחלון גלישה בסתר (חלון רגיל נוסף עשוי לשתף את אותו משתמש אנונימי של המתרגל). ענו, חשפו תשובה וודאו שהניקוד התעדכן בשני המכשירים.

## סיוע בתקלות

- **"דרושה הגדרה חד־פעמית":** `firebase-config.js` עדיין מכיל ערכי `PASTE_`. בדקו שהעליתם את כל הקבצים ושהם באותה תיקייה כמו `index.html`.
- **`permission_denied`:** בדקו שפרסמתם את הכללים מ־`database.rules.json` ב־**Realtime Database → Rules**; שההתחברות האנונימית פעילה; ושמסד הנתונים הוא זה שהכתובת שלו כתובה ב־`databaseURL`.
- **"לא נמצא חדר":** בדקו את הקוד, או צרו חדר חדש. חדר שמחקו לא ניתן לשחזור.
- **הניקוד לא משתנה:** הוא משתנה לאחר שהמתרגל **חושף** את התשובה, לא מיד עם ההצבעה.
- **למורה אין אפשרות להמשיך אחרי סגירת הטאב:** פתחו מחדש את האתר *באותו דפדפן ובאותו פרופיל*, הקישו על המשחק הכיתתי, והחדר הקודם ייפתח אם זהות Firebase האנונימית נשמרה. אם נמחקו נתוני הדפדפן, פתחו חדר חדש.
- **העדכונים לא מופיעים:** דרוש חיבור לרשת בזמן המשחק. רענון הדף בדרך כלל עוזר. ייתכן שהדפדפן שומר גרסה ישנה — נסו רענון מאולץ (`Ctrl+F5`).

## עלויות, פרטיות והוגנות

- **Firebase Realtime Database בתוכנית Spark תומך ב־100 חיבורים בו־זמנית לכל מסד נתונים**, כולל מכשיר המתרגל. לכיתה גדולה יותר צריך פתרון בעל קיבולת גבוהה יותר. יש גם מכסות נוספות של שימוש והתחברות אנונימית; ראו [Firebase Pricing](https://firebase.google.com/pricing) ו־[Realtime Database limits](https://firebase.google.com/docs/database/usage/limits).
- אין צורך בשמות אמיתיים או בהרשמה. נשמרים כינוי, מזהה אנונימי, תשובות וניקוד מחושב ממענה; בעלי קוד החדר יכולים לראות את הכינויים והתשובות. **אל תאספו נתונים רגישים או תשתמשו בזה למבחן עם ציון רשמי.** הבחירה הנכונה נמצאת גם בקוד האתר, ולכן שחקן מיומן יכול למצוא אותה.
- הניקוד מחושב באופן אחיד בכל המכשירים: **100 נקודות לכל תשובה נכונה**, ללא בונוס למהירות; ניתן להיות בתיקו.
- כללי המסד מגבילים מתן תשובות רק למשתתפים בחדר, פעם אחת לשאלה, ורק בשלב ההצבעה. הם אינם מערכת נגד רמאות (משתמש יכול לנסות להצטרף בכמה דפדפנים).
- סגירת החדר מהמסך האחרון מוחקת את התשובות ואת הכינויים, אך אינה מוחקת את חשבונות Firebase האנונימיים. רצוי למחוק חדרים ישנים לאחר השיעור.

## למי שרוצה לשנות שאלות

ב־`index.html` מערך `QUESTIONS` מכיל תשע שאלות, סוג אי־הרציפות, הגרף וההסבר; `makePlot()` מצייר SVG. אם משנים את מספר השאלות, מומלץ להתאים טקסטים בהוראות. אין תלות בספריות גרפים חיצוניות. קובץ `live.js` מטפל בחדרים, בהצבעות, בסנכרון ובדירוג.
